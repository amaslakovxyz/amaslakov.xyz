# Дизайн: лендинг-hero для amaslakov.xyz + готовность к релизу

- Статус: утверждён (направление), ожидает ревью спеки
- Дата: 2026-10-22
- Ветка: `feat/landing-hero`
- Трек: Medium (multi-file, PR) + ADR

## 1. Контекст и цель

Блог технически зрел: FastAPI + HTMX, контент в Markdown+frontmatter, чистое
разделение `core/` (pure) и `shell/` (I/O), тесты, CI/CD через Ansible на
self-hosted runner. Голой осталась главная: в `web/templates/xyz/index.html`
стоит `[ landing placeholder — design later ]`.

Цель — заменить заглушку на минималистичный, но характерный hero в стиле
«neofetch-персона»: холодная фиолетово-синяя многоцветная палитра,
терминальный и номадский характер. Плюс закрыть оставшиеся пробелы до
финального релиза (meta/OG, favicon, 404, robots, sitemap).

Тон интро — «кто я + чем занят сейчас». Текст Anton впишет сам; задача дизайна —
красивая форма с аккуратными слотами под текст.

## 2. Дизайн hero (neofetch-lite)

Утверждённое направление — склейка вариантов A (радикальный минимализм) и D
(терминал/mono) с «neofetch для человека» в центре. Референс-мокап:
`thread-storage/reports/hero-final.html`.

Композиция главной (`index.html`), сверху вниз:

1. **Prompt-строка** — `~ whoami` mono, мигающий курсор (блок-акцент).
2. **Имя** — крупный `<h1>`, градиент violet→blue→cyan по тексту. Слот.
3. **neofetch-блок** — две колонки (на узком экране схлопывается в одну):
   - слева: ASCII/ANSI-логотип (статичная разметка, многоцветный);
   - справа: info-строки `key: value` —
     `role` (слот), `now` (слот), `loc` (метка + координаты),
     `local` (живые часы по IANA-таймзоне), `stack`, `essays` (счётчик).
4. **ANSI-палитра** — ряд цветных блоков (фирменный «штрих-код»).
5. **Ряд ссылок-иконок** — essays · github · email · rss, тонкие line-SVG,
   каждая своего цвета.
6. **ASCII-разделитель** — `╌╌╌ ◆ ╌╌╌`.
7. **`latest`** — существующий список постов (`shared/_items.html`),
   заголовок в mono-стиле.

Подвал (`base.html`): добавляется тонкий **статус-бар** —
`⎇ main · ● deployed Nd ago · # <sha> · ↑ uptime`, цвета разные. Данные
опциональны (см. §4): если их нет — бар скрыт.

**Анимация «открытия»**: элементы hero всплывают снизу со сдвигом opacity,
staggered-задержка. Обязательно уважать `prefers-reduced-motion: reduce` —
при нём анимация и мигание курсора отключаются.

**Живые часы**: `Intl.DateTimeFormat` с `timeZone` из конфига (IANA, напр.
`Asia/Tbilisi`), обновление раз в секунду. Без внешних зависимостей.

## 3. Палитра (холодная, violet/blue, многоцветная)

Сейчас `xyz.css` — тёплая. Меняем скин `xyz` на холодный для обеих тем.
`base.css` остаётся нейтральным дефолтом/фолбэком.

Dark (основная):
```
--bg:#0f0e17; --fg:#e8e6f5; --muted:#9a95b8; --border:#262238;
--code-bg:#141222; --accent:#8b7cf6;
--c-violet:#8b7cf6; --c-blue:#5b8cff; --c-cyan:#3fd0d6;
--c-green:#6ee7a8; --c-yellow:#f5c66b; --c-pink:#f472b6; --c-red:#fb7185;
```
Light: те же `--c-*` (чуть темнее для контраста на светлом), светлый
`--bg`/`--fg`, акцент — тот же violet. Контраст текста проверяем на AA.

## 4. Изменения данных (dry facts, конфиг)

Hero требует данных, которых нет в `SiteConfig`. Добавляем поля (все —
«сухие факты», допустимо доктриной):

- `role: str` — строка «кто я» (сейчас слот/плейсхолдер).
- `now: str` — строка «чем занят сейчас».
- `location: Location | None` — `{ label: str, coords: str, tz: str }`
  (IANA tz для часов). Правится при переезде.
- `links: Links` — `{ github: str | None, email: str | None }`
  (rss и essays уже выводятся).
- `stack: tuple[str, ...]` — напр. `("Python", "FastAPI", "HTMX")`.

Статус-бар (опционально, из env через `Settings`):
- `BLOG_GIT_SHA` и `BLOG_DEPLOYED_AT` — проставляются при деплое (Ansible).
  Если переменных нет (локально) — бар не рендерится. Это держит core pure,
  а факты — на границе.

`core/` остаётся pure: новые поля — обычные frozen-dataclass/`Literal`.
Валидация env — в `shell/config.py` (pydantic-settings, как сейчас).

## 5. Готовность к релизу — чеклист

В scope этого PR (Phase 1):

- [ ] Hero (§2) + палитра (§3) + данные (§4).
- [ ] **Кастомная 404** — сейчас `HTTPException(404)` отдаёт голый JSON.

## 6. Инфраструктура

Текущее (работает): systemd `blog-xyz.service` на `127.0.0.1:8734` из
`/srv/blog-xyz`; nginx/TLS — в `ex-infra`; деплой — GitHub Actions
(self-hosted runner) → Ansible `release.yml`; плюс ручной `just deploy`.

Нужно для этого PR:
- Прокинуть `BLOG_GIT_SHA`/`BLOG_DEPLOYED_AT` в окружение сервиса при деплое
  (Ansible `release.yml` / systemd env) — для статус-бара. Если решим
  отложить — статус-бар просто не рендерится, деградация мягкая.
- Убедиться, что статика (`favicon`, `og-image`) отдаётся через `/static`.

Nginx/TLS-правки (если понадобятся заголовки кэша для статики) — отдельная
инфра-операция в `ex-infra`, не в этом репозитории.

## 7. Тесты

- Boundary: `SiteConfig`/`Settings` с новыми полями валидируются; отсутствие
  env → `git_sha is None`.
- App: `GET /` рендерит hero (есть `whoami`, имя, info-ключи); 404 отдаёт
  HTML-страницу, не JSON; `GET /robots.txt` и `GET /sitemap.xml` 200 с
  корректным content-type; sitemap содержит URL поста.
- Core (golden): sitemap-рендер детерминирован для набора постов.
- Существующие тесты (feed, loader, markdown, sites) не ломаются.
